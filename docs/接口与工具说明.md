# 接口与工具说明

本说明用于连接 `submission/` 作答工程、公共运行程序和结果采集工具。所有命令在 `/home/project/exam` 执行，文件路径也以该目录为起点。`submission/app.py` 是服务入口，`submission/config.json` 是配置文件，`submission/src/policy.py` 是业务实现位置。

## 启动和采集

平台自动准备模型、依赖和 `submission/`。完成相应代码及配置后运行以下命令。

```bash
bash tools/start.sh
```

启动脚本使用预装环境，监听 8080 端口，显示服务状态并记录实际进程。修改代码、配置或模板后执行 `bash tools/start.sh restart`。查看状态使用 `bash tools/start.sh status`，停止服务使用 `bash tools/start.sh stop`。原始入口 `submission/app.py` 支持 `--host`、`--port` 和 `--resources`，供需要指定运行位置时使用。

每题结果用同一采集命令保存，只需替换题号。

```bash
python tools/results.py --question 0101
```

工具读取当前工程或服务，采集成功后自动写入 `submission/answers/0101.txt`，并显示保存路径。0402 自动识别启动脚本记录的服务进程，也可用 `--pid` 指定实际进程。0501 采集通过真实浏览器提交指定网页问题并核对显示。采集失败会报告原因，已有结果文件保留。

交卷前执行以下命令。服务需已经启动。

```bash
python tools/package.py
```

打包工具重新采集当前可取得的逐题结果，最后更新 0502 工程主体摘要，生成 `submission/manifest.json` 和 `submission.zip`。某题采集失败时，会列出失败原因并保留该题已有结果或空文件，其他已完成成果仍可打包。终端中的保存路径和错误信息可用于核对本次采集状态。

## HTTP 请求约定

服务地址为 `http://127.0.0.1:8080`，网页从同一服务调用接口。POST 请求的 `Content-Type` 为 `application/json`，正文为 1 至 16384 字节的 UTF-8 JSON 对象。请求只包含对应接口列出的字段。JSON 字段名不能重复，数值须有限，布尔值与整数分别校验。

| 情况 | HTTP 状态及响应 |
| --- | --- |
| 合法请求完成 | 200，返回对应接口结果 |
| JSON、字段、类型或取值有误 | 400，返回含 `error` 字符串的 JSON 对象 |
| 该接口需要的模型或规则索引未就绪 | 503，返回含 `error` 字符串的 JSON 对象 |

`question` 和 `texts` 内的文本以 Python `str.strip()` 去掉首尾空白后检查长度，再用于编码和查询，内部空格、标点和大小写保持输入原样。此处理在本题中称为文本规范化。缺省和显式 `null` 对馆点字段均表示缺项，空字符串属于无效馆点值。

接口机器约束见 `docs/openapi.json` 和 `docs/api_contract.schema.json`，服务也通过 `GET /openapi.json` 提供接口定义。

## 健康状态

`GET /health` 返回模型、索引、缓存及当前进程的实际计数。

| 字段 | 含义 |
| --- | --- |
| `ready` | 模型是否实际加载且可用于编码，布尔值 |
| `dimension` | 向量维度，固定为 312 |
| `index_loaded` | 当前规则索引是否已加载，布尔值 |
| `model_loads` | 当前进程的模型加载次数 |
| `query_encodes` | 当前进程中问题和 `/embed` 输入实际编码的文本条数 |
| `doc_encodes` | 当前进程中实际重新编码的资料条数 |
| `cache_hits` | 当前进程的问题缓存命中次数 |
| `cache_entries` | 当前缓存条目数 |
| `cache_size` | 当前配置的缓存容量 |
| `reuse_index` | 当前资料向量复用配置，布尔值 |

模型就绪和索引加载分别记录。`/embed` 需要模型就绪，`/answer` 同时需要模型与索引就绪。计数字段为非负整数，重启进程后重新记录。清空缓存只清条目，保留当前进程的累计计数。

## 文本编码

`POST /embed` 的唯一请求字段为 `texts`，包含 1 至 4 条字符串，每条文本规范化后为 1 至 200 个字符。例如，可提交下列请求。

```json
{"texts":["普通纸质书的跨馆归还","随书光盘原馆归还"]}
```

响应字段为 `dimension` 和 `vectors`，前者为 312，后者每行对应一条输入文本，行序与输入一致。每行含 312 个有限数值。

统一编码使用本地模型目录 `models/course_semantic_model/`，设备为 CPU。Tokenizer 的首段为空字符串，次段为实际编码文本，最大长度为 128，启用截断并填充至该长度。取模型末层序列输出首位置的 CLS 表示，转换为 `float32` 后作 L2 归一化。

L2 归一化先计算向量各元素平方和的平方根，再将每个元素除以该长度，即 `v[i] = x[i] / sqrt(sum(x[j] * x[j]))`。输入向量须为非零向量。归一化后每行的 L2 长度与 1 的绝对误差不超过 `0.0001`，向量数值比对采用公开的浮点容差 `0.0001`。

## 答复预览

`POST /preview` 用于检查模板、候选限制和长度限制。必需字段为 `answer` 和 `sources`，可选字段为 `candidates`。

| 字段 | 约定 |
| --- | --- |
| `answer` | 1 至 2000 个字符的单行正文 |
| `sources` | R01 至 R12 的规则编号数组，元素不重复，可为空 |
| `candidates` | 候选对象数组，元素含 `id` 和 `score`，省略时为空数组 |

候选编号为 R01 至 R12，不能重复。`score` 为 [-1,1] 范围内的有限数值，候选按分值从高到低排列。服务按当前最低相关度和数量上限过滤候选。`sources` 取自预览请求提供的规则编号。

下列请求用于独立验证两行答复。

```json
{"answer":"可在西馆归还。","sources":["R01"]}
```

响应包含渲染后的 `answer`、来源数组 `sources` 和过滤后的 `candidates`。预览使用给定的模拟正文与候选，无需先加载规则索引。完整的固定预览输入位于 `data/public_cases.json` 中的 `preview_format` 和 `preview_limits`。

## 归还咨询

`POST /answer` 接收下列字段。

| 字段 | 约定 |
| --- | --- |
| `question` | 必需，文本规范化后为 1 至 200 个字符 |
| `borrow_branch` | 可选，借出馆代码 E、W、S 或 `null` |
| `return_branch` | 可选，拟还馆代码 E、W、S 或 `null` |

馆点由两个馆点字段提供。问题文本表达咨询事项和馆藏类别，允许日常同义表达。例如，东馆借出的普通纸质书计划在西馆归还，可提交下列请求。

```json
{"question":"普通纸质书能在这儿还吗？","borrow_branch":"E","return_branch":"W"}
```

正常响应含 `decision`、`return_to`、`missing_fields`、`sources`、`answer` 和 `candidates`。各结论的字段含义如下。

| `decision` | 对应结果 |
| --- | --- |
| `ALLOW` | `return_to` 为拟还馆，`sources` 含决定性规则，`missing_fields=[]` |
| `DENY` | `return_to` 为原借出馆，`sources` 含决定性规则，`missing_fields=[]` |
| `NEED_INFO` | `return_to=null`、`sources=[]`，`missing_fields` 列出范围内咨询的全部缺项 |
| `OUT_OF_SCOPE` | `return_to=null`、`sources=[]`、`missing_fields=[]` |

`missing_fields` 按 `borrow_branch`、`return_branch`、`item_type` 排列，中文名依次为“借出馆”“拟还馆”“馆藏类别”。仅使用“这个”“借的东西”等指代时，馆藏类别仍是缺项。明确的资料范围外请求先返回 `OUT_OF_SCOPE`，例如“电子书怎么续借？”。

`candidates` 表示经阈值和数量上限过滤的实际候选资料，格式与预览一致。`sources` 为支持答复的资料编号，实际来源应出现在候选中。每个未缓存的合法问句实际经过模型编码，模型参与适用资料的召回和选择。

## 配置与两行答复

`submission/config.json` 保存模型、检索、答复及缓存设置，`submission/prompts/answer.txt` 保存答复模板。配置和模板在服务启动时加载，修改后重启生效。

| 配置字段 | 类型与含义 |
| --- | --- |
| `model_enabled` | 布尔值，是否启用指定模型 |
| `device` | 字符串，使用 `cpu` |
| `max_length` | 整数，文本最大编码长度 |
| `prefix` | 字符串，答复前缀 |
| `top_k` | 整数，候选资料的数量上限 |
| `min_score` | 有限数值，最低相关度阈值 |
| `max_answer_chars` | 整数，完整答复的字符数上限 |
| `index_path` | 相对于 `submission/` 的索引路径 |
| `reuse_index` | 布尔值，是否复用资料向量 |
| `cache_size` | 整数，问题缓存容量 |

模板接受 `{prefix}`、`{answer}` 和 `{sources}` 三个占位符。正式第一行是“【馆藏归还】”直接连接正文，第二行是“资料：”直接连接来源编号。多个编号用中文顿号“、”连接，顿号两侧均无空格，例如“资料：R01、R03”。空来源时为“资料：无”。

正文首句按实际业务结果填写，相容的简短补充说明可接在后面。

| 业务结果 | 正文首句格式 |
| --- | --- |
| `ALLOW` | `可在{馆名}归还。` |
| `DENY` | `该馆不接收，请到{馆名}归还。` |
| `NEED_INFO` | `请补充{缺项中文名}。` |
| `OUT_OF_SCOPE` | `资料未收录该事项。` |

缺项有多项时，也用中文顿号“、”直接连接，顿号两侧均无空格，例如“请补充借出馆、拟还馆。”。前缀、正文和资料行共同计入长度。正文过长时优先截去补充文字，保留业务结论、前缀和完整来源行。预览与实际问答共用该规则。

## 知识索引

索引是提前算好的资料向量及其身份信息，供每次咨询重复使用。`submission/artifacts/index.npz` 保存名为 `vectors` 的 `12×312`、`float32` 矩阵，各行与 `data/rules.jsonl` 的非空行顺序对应，并按统一模型约定编码和归一化。资料编码文本为 `title + "：" + text`，全角冒号两侧不额外添加空格。

在完成所需模型配置后，使用公共工具建立索引。

```bash
python tools/build_index.py
```

`submission/artifacts/index.meta.json` 包含 `rows`、`dimension`、`dtype`、`doc_ids`、`index_sha256`、`rules_sha256`、`model_sha256`、`device` 和 `max_length`。`index_sha256` 为索引原始字节的 SHA-256，`rules_sha256` 为资料原始字节的 SHA-256，`model_sha256` 为 `models/course_semantic_model/model_state.pdparams` 原始字节的 SHA-256。`doc_ids` 按资料行序记录规则编号。

配置中的 `index_path="artifacts/index.npz"` 是相对于 `submission/` 的值，对应本文路径 `submission/artifacts/index.npz`。模型、资料或编码设置发生变化后，索引应与新资源重新对应。

## 缓存与性能

文本规范化后的问题、借出馆和拟还馆共同区分一次咨询。三项相同才可复用相应答复。`POST /cache/clear` 接收空对象 `{}`，返回 `{"cache_entries":0}`。容量控制、淘汰与清空后的重算按实际行为检查。

性能采集使用 `data/public_cases.json` 的 `benchmark` 输入，先预热两轮，再采集 24 次串行请求和 4 个客户端的 24 次热缓存请求。每次串行请求前清空答复缓存，热缓存请求前将样例答案写入缓存。预热不计入串行时延，失败样本保留。响应结论、归还馆、缺项、来源和答复均须有效。

串行结果统计平均值和 P95。将 24 次时延从小到大排列，P95 取第 `ceil(24×0.95)` 项。服务进程及其子进程 RSS 每 50 毫秒采样一次，以采样峰值记录内存。每次请求超时为 12 秒，实际业务有效性至少为 80% 才进入性能评价。时延和内存可随环境产生浮动。

使用结果工具即可测量并保存 0402。

```bash
python tools/results.py --question 0402
```

## 工程主体摘要

`payload_sha256` 用于描述本次提交的工程主体。计算范围是打包范围内的实际工程文件，先排除整个 `submission/answers/` 和 `submission/manifest.json`，再按以下方法计算。

1. 文件名使用相对于 `submission/` 的路径，目录分隔符为正斜杠。例如配置文件的键为 `config.json`，网页的键为 `web/index.html`。
2. 对每个文件的原始字节计算 SHA-256，得到 64 个小写十六进制字符。
3. 建立“相对路径到文件摘要”的 JSON 对象，将键按升序排列。以 `json.dumps(mapping, sort_keys=True, separators=(",", ":"), ensure_ascii=False)` 序列化，使用 UTF-8 编码。该 JSON 无额外空白或结尾换行。
4. 对这段 UTF-8 字节再次计算 SHA-256，所得 64 位小写十六进制字符串即为 `payload_sha256`。

可用以下命令生成并保存 0502，最后打包时还会按工程现状更新该结果。

```bash
python tools/results.py --question 0502
```

`submission/manifest.json` 中的 `files` 使用相同的工程内相对路径，覆盖最终包中的所有实际文件，清单自身除外，其中包括已提交的答案文件。

## 结果与交卷范围

各题输出写入 `submission/answers/题号.txt`，每份最多 65536 字节，采用 UTF-8。0201 为两行纯文本，其余各为一个 JSON 对象。未完成的文件可留空或省略。`python tools/check.py` 可检查已保存结果的格式。

允许的工程根文件为 `submission/app.py`、`submission/config.json`、`submission/README.md`、`submission/manifest.json`，子目录为 `submission/prompts/`、`submission/src/`、`submission/web/`、`submission/artifacts/`、`submission/answers/`。文件类型范围为 `.py`、`.json`、`.txt`、`.md`、`.html`、`.css`、`.js`、`.npz`、`.svg`、`.png`、`.jpg`，答案目录仅接受 10 个规定题号的 TXT。

`submission.zip` 解压后的唯一顶层目录为 `submission/`。压缩及解压后的文件总量分别不超过 20 MiB，实际文件最多 200 个。日志、缓存和运行状态留在运行目录中。原始模型、资料、公共程序和 Python 环境使用各自的公共资源位置。交卷文件全部采用普通文件，文本使用 UTF-8。
